New prediction pipeline

01

Generate broadly

The n-gram beam is widened so junk candidates do not exhaust the pool before useful words appear.

02

Fence by vocabulary

Only entries in vocab_lower_100k.txt survive.

03

Require exact prefix

A completion must begin with the text the user already typed.

04

Bucket and cap

Keep at most three words per key, then retain the global top 17 by probability.

Before

  • Character beam output was treated as a word list.
  • Prefixes such as tod produced toda, todb … todz.
  • The adapter applied a three-per-key limit but no global limit.
  • Average screen load was 41.5 word clocks.

After

  • Every displayed completion belongs to the same vocabulary used by legacy KenLM.
  • Every completion extends the typed prefix.
  • The global num_words_total contract is enforced.
  • Average TextSlinger screen load is now 15.6 word clocks.

Core adapter logic

Candidate rejection

if (
    not word
    or len(word) <= prefix_len
    or not word.startswith(prefix.lower())
    or word.lower() not in self.vocabulary
):
    continue

Legacy-compatible display cap

bucketed_candidates.sort(
    key=lambda candidate: candidate[1],
    reverse=True,
)
kept_words = {
    word
    for word, _ in bucketed_candidates[:num_words_total]
}
